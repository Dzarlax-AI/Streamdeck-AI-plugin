3. Контракт платформ и ограничения

Захват выделения будет проверяться через NSPasteboard.changeCount на macOS и GetClipboardSequenceNumber на Windows. Команды запускаются через существующие системные средства: /usr/bin/osascript и Windows PowerShell. Не добавляются нативные npm-зависимости или обязательная установка PowerShell 7.

Проверки Windows должны покрывать штатный путь SystemRoot, пробелы в пути, аргументы без shell-интерполяции пользовательского текста, Unicode, переносы строк и завершающие пробелы. Чтение Windows-буфера должно возвращать исходный текст, без потери данных из-за trimEnd(). Это часть сохранения корректности пути захвата, а не отдельная функция.

Счётчик фиксирует изменение буфера, но не доказывает, что его создал именно текущий редактор. Несогласованный снимок или недоступный счётчик должны приводить к отказу без отправки текста. На macOS по-прежнему нужны права Accessibility для эмуляции клавиш; на Windows действуют ограничения доступа и уровня привилегий приложений.

В среде доступен macOS. Пользователь подтвердил наличие Windows-компьютера; удалённый доступ не предоставлен. Stream Deck физически подключён к другому Mac. Автотесты выполнят обе ветки с подставленными системными процессами. Это не заменяет реальное испытание Ctrl+C/Ctrl+V в Windows и не будет названо полной нативной проверкой.

Блокирующих продуктовых вопросов для этого объёма нет: выбор сделан в пользу отказа при неподтверждённом захвате и отклонения повторного запуска.

6. Риски и восстановление

  • Некоторые приложения обновляют буфер с задержкой. Ожидание должно быть ограничено; при сомнении операция завершится ошибкой вместо передачи старого текста.
  • Параллельный запуск теперь отклоняется. Это намеренное изменение поведения; очереди и отложенной вставки не будет.
  • Custom URL с proxy-префиксом должен сохранить путь. Проверить базовый URL и уже полный endpoint, не допуская удвоения суффикса.
  • После API-запроса фокус может смениться, и автоматическая вставка всё ещё попадёт в текущее окно. Это существующий отдельный риск; защита фокуса перечислена ниже как предложение.
  • Восстановление — обратный патч только к исходникам этого изменения; не использовать git reset --hard, не восстанавливать docs и не отменять изменение release workflow. Установленный плагин и производство не изменяются.

Предлагаемая схема автопроверки

  1. Node-адаптеры провайдеров. Одна реализация авторизации, URL, pagination, получения моделей и метаданных для кнопки и энкодера, общая с генерацией. Browser Inspector передаёт команды через существующий WebSocket и отображает ответ. Это устраняет CORS-расхождение Fetch и Test connection. Никаких внешних промежуточных сервисов.
  2. Нормализованные сведения. ID, поддержка text-in/text-out и существующего API, lifecycle, токенные ограничения, поддержка/диапазон temperature и источник сведений. Неизвестное остаётся unknown; отсутствие поля не объявляется unsupported. Не подбирать другой провайдер или модель автоматически. Responses-миграция в этот этап не входит.
  3. Два явных уровня проверки. Проверка доступа/каталога выполняет только GET. Отдельная кнопка «Проверить генерацию — использует токены» отправляет фиксированные безличные system/user строки, не содержимое буфера и не пользовательский промпт. Используются тот же генератор запроса и выбранные настройки; бюджет проверки — 1 выходной токен для известной обычной модели, до 128 для reasoning-модели или неизвестных возможностей. Автоматического увеличения лимита нет. Для reasoning этот бюджет включает скрытые токены. Пустой ответ — inconclusive. Непустой текст при остановке по малому лимиту подтверждает проверочный запрос; обычные действия по-прежнему отклоняют обрезанный результат.
  4. Ограниченная адаптация. По метаданным заранее не включать неподдерживаемые optional-поля. Если тест вернул структурированную ошибку unsupported_parameter для разрешённого необязательного поля, предложить/показать исключение этого поля и допустить не больше одной повторной попытки. Максимум две попытки на одно нажатие. Не обходить ошибки ключа, оплаты, доступа, rate limit, модели или API URL. Не менять model, endpoint, thinking/reasoning effort или основные пользовательские лимиты молча.
  5. Профиль текущей конфигурации. Кэш результата на сессию в памяти, TTL один час; привязка к провайдеру, model ID, endpoint, API version и настройкам запроса. Смена ключа, URL, модели, temperature или лимита сбрасывает проверенный статус. Ключ не копируется в отдельное хранилище и не попадает в логи. Постоянные credential profiles и миграция настроек не входят.
  6. Прозрачный UI. Показывать «Каталог доступен», «Генерация проверена», «Проверка не завершена» или конкретную безопасную ошибку. Выключать неподдерживаемые контролы с объяснением и показывать фактически используемые параметры. Ручной ввод модели доступен для всех провайдеров; сохранённый выбор не заменяется скрытно.
  7. Корректный вывод. Собирать все текстовые блоки ответа, исключать thinking/non-text. Пустой, заблокированный или обрезанный результат не заменяет выделение и не стирает буфер; ошибка отличается от сетевого сбоя.

Файлы: src/api-client.ts и новый изолированный provider-capabilities.ts; src/plugin.ts для команд каталога/проверки; оба Inspector и общий shared-settings.js; тесты адаптеров, UI и SDK loopback; README и этот план. Формат существующих глобальных ключа/модели/endpoint сохраняется. Новые ответы команд содержат requestId, status и нормализованные capabilities, без credential payload.

Координатор — интеграция, независимая проверка диффа и SDK/browser QA. Согласование зафиксировано; live-запросы с пользовательским ключом выполняет сам пользователь явным нажатием отдельной кнопки.

Риски и откат: метаданные могут устаревать, Custom и роутеры могут игнорировать поля, reasoning может исчерпать проверочный лимит. Результат тогда ограничен подтверждённым сценарием. Откат — убрать новый capability/probe слой отдельным обратным патчем, сохранив восемь базовых исправлений, версию SDK и UI. Коммит, push, PR, установка и публикация по-прежнему требуют отдельного разрешения.

Решение: отдельная кнопка проверки генерации с минимальным бюджетом 1/128. Максимум одна повторная попытка только после явного structured unsupported_parameter для temperature. Проверка не подтверждает полный пользовательский лимит вывода или семантическую поддержку полей Custom-сервером.

Источники: метаданные OpenRouter; метаданные Gemini; каталог Claude; Anthropic CORS; ограничения sampling Claude; совместимость OpenAI.
