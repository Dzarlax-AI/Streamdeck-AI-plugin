### 1. Концепция
Плагин работает как "невидимый посредник" между пользователем и API провайдера (OpenAI, Anthropic, OpenRouter). Основной инструмент взаимодействия — **манипуляция буфером обмена** и **эмуляция нажатий клавиш**.

### 2. Функциональные требования

#### 2.1. Ядро (Workflow Engine)
Плагин должен поддерживать два основных сценария обработки текста:

1.  **Режим "Selection" (Обработка выделенного):**
    *   Шаг 1: Эмуляция `Cmd+C` (macOS) / `Ctrl+C` (Windows).
    *   Шаг 2: Захват текста из системного буфера обмена.
    *   Шаг 3: Отправка текста в API с заданным промптом.
    *   Шаг 4: Получение ответа.
    *   Шаг 5: Запись ответа в буфер обмена.
    *   Шаг 6 (Опционально): Эмуляция `Cmd+V` / `Ctrl+V` (замена текста).

2.  **Режим "Clipboard" (Обработка буфера):**
    *   То же самое, но без Шага 1. Плагин берет то, что *уже* лежит в буфере обмена. Полезно для контекстного меню "Копировать -> Обработать".

#### 2.2. Настройка API (Global Settings)
В глобальных настройках плагина (профиль пользователя) должны быть поля:
*   **Provider:** Выбор из списка (OpenAI, Anthropic, Custom OpenAI-compatible).
*   **API Key:** Поле для ввода ключа (с маскировкой).
*   **Base URL:** (Для продвинутых) Возможность указать свой эндпоинт (например, для локального Ollama или прокси).
*   **Model:** Текстовое поле для названия модели (например, `gpt-4o`, `claude-3-5-sonnet-20241022`).
*   **Default Parameters:** Temperature, Max Tokens (глобально для всех кнопок).

#### 2.3. Конфигурация кнопки (Property Inspector)
При перетаскивании действия на дек, пользователь настраивает:
*   **Action Name:** Название кнопки (отображается на иконе).
*   **System Prompt:** Большое текстовое поле для инструкции (напр., "Ты редактор...").
*   **User Prompt Template:** Шаблон с переменными.
    *   Поддержка плейсхолдера `{{text}}` (вставка захваченного текста).
    *   Пример: "Переведи следующий текст на русский: \n\n{{text}}".
*   **Post-action Behavior:**
    *   `Paste` (Вставить сразу — режим "Замена").
    *   `Copy Only` (Положить в буфер, не вставлять).
    *   `Show Result` (Показать результат в модальном окне Stream Deck).

#### 2.4. Поддержка Stream Deck+ (Кноб/Энкодер)
Реализовать действие "Prompt Selector" для экранного кноба:
*   **Дисплей:** Показывает название текущего активного промпта.
*   **Вращение:** Переключение между сохраненными промптами (список берется из настроек или предустановок).
*   **Нажатие:** Выполнить действие с текущим выбранным промптом над выделенным текстом.

### 3. Интерфейс и Обратная связь (UI/UX)

Пользователь должен понимать состояние плагина без задержек.
*   **Состояние 1: Idle.** Статичная иконка.
*   **Состояние 2: Processing.** Анимированная иконка (Spinner) или смена цвета фона (синий/фиолетовый). Показывает, что запрос ушел в сеть.
*   **Состояние 3: Success.** Зеленая галочка (на 1.5 сек), затем возврат к Idle.
*   **Состояние 4: Error.** Красный восклицательный знак (на 3 сек). В идеале — показать Toast-уведомление на экране компьютера с текстом ошибки (API limit, wrong key).

### 4. Нефункциональные требования

#### 4.1. Быстродействие
*   Задержка между нажатием и эмуляцией `Ctrl+C` должна быть минимальной (<50мс).
*   Таймаут ожидания ответа от API: 30 секунд (с возможностью настройки).

#### 4.2. Безопасность
*   API ключи не должны сохраняться в открытом виде в `manifest.json` или файле настроек, читаемом текстом (использовать `streamDeck.settings` с базовым шифрованием или системное хранилище ключей, если возможно).

#### 4.3. Совместимость
*   Поддержка Windows 10/11 и macOS (последние 3 версии).
*   Корректная работа с кириллицей и спецсимволами в буфере обмена (UTF-8).

### 5. Библиотека предустановок (Presets)

Чтобы пользователю не писать промпты с нуля, плагин должен поставляться с библиотекой готовых действий (Drag & Drop):
1.  **Fix Spelling & Grammar:** (System: You are a proofreader... Action: Paste).
2.  **Translate to English:** (System: Translate to English... Action: Paste).
3.  **Summarize:** (System: Summarize in 3 bullet points... Action: Copy Only / Show Result).
4.  **Explain Code:** (System: Explain this code... Action: Show Result).
5.  **Change Tone (Professional):** (System: Rewrite professionally... Action: Paste).

### 6. Ограничения версии (Out of Scope)
В этой версии мы **осознанно не делаем**:
*   Скриншоты экрана и анализ изображений (Vision) — это требует нативного агента.
*   Работу с файлами напрямую (открыть файл -> прочитать -> обработать).
*   Переключение профилей Stream Deck в зависимости от активного окна (Context Awareness).
*   Историю чата (Chat History) — каждое нажатие это новый запрос без памяти предыдущих.

### Технический стек для разработки (Рекомендации)

1.  **Язык:** JavaScript/TypeScript (Node.js).
2.  **SDK:** [Stream Deck SDK](https://developer.elgato.com/documentation/stream-deck/sdk/overview/).
3.  **Библиотеки:**
    *   `axios` или `fetch` для API запросов.
    *   `robotjs` или нативные методы SD SDK для эмуляции клавиш (копирование/вставка).
    *   `marked` (опционально) для рендеринга Markdown в окне предпросмотра результата.

Это ТЗ дает четкий roadmap для создания надежного, полезного продукта, который решает 80% рутинных задач (работа с текстом) без сложностей разработки десктопного приложения.
